# /portal-init

Bootstrap a knowledge base. Run from the directory you want the KB to live in (typically `<team-root>/knowledge-base/` or alongside your team-knowledge brain).

## Phase 0 — Confirm location + naming

1. `pwd` and confirm the path.
2. If the directory is non-empty, list contents and confirm.
3. Ask for the **domain name** (free text, e.g. "Shoplit Recommendations") and a **slug** (kebab-case).

## Phase 1 — Scaffold layout

Create:

```
./
├── README.md                              # overview, regenerated from templates
├── knowledge_base_architecture.md         # design doc — included so future maintainers know why
├── knowledge/
│   ├── domain_knowledge.md                # from templates/knowledge_topic.md.tmpl (one per topic)
│   ├── systems_and_models.md
│   ├── metrics_and_measurement.md
│   ├── people_and_org.md
│   ├── processes_and_rituals.md
│   ├── gotchas_and_tips.md
│   ├── resources.md
│   ├── skills.md
│   ├── industry_landscape.md
│   ├── intake.md
│   ├── conflict_log.md
│   └── deep_dives/                        # empty — use /portal-add-explainer or hand-add
├── portal/
│   ├── build_portal.py                    # copy from plugin's portal/build_portal.py
│   ├── index.html.tmpl                    # copy from plugin
│   ├── explainer.html.tmpl                # copy from plugin
│   └── explainers/                        # one HTML file per subject, generated by /portal-add-explainer
└── auto_discovery/
    ├── auto_discovery_playbook.md         # short pointer doc: how this KB stays fresh
    └── auto_discovery_findings.md         # log of recent discovery passes
```

For each topic markdown, fill in the topic name in the template and leave a `<!-- TODO: fill in -->` marker in each section.

## Phase 2 — Wire to a team-knowledge brain (optional)

Ask: "Are you also using the `team-knowledge` plugin?"
- If YES — symlink (or just point) `knowledge/intake.md` and `knowledge/conflict_log.md` to the brain's files of the same name. Both plugins use the same schema.
- If NO — keep the local copies.

## Phase 3 — Build the initial portal

Run `/portal-build` so the user sees an empty-but-working `portal/index.html` immediately. The empty portal is the spec — it makes the "what goes where" question concrete.

## Phase 4 — Next steps

Print:

```
Knowledge base scaffolded at <path>.

Next:
  1. Open knowledge/domain_knowledge.md and fill it in
     (every topic file has TODO markers — work through them in any order)
  2. Add subject explainers:   /portal-add-explainer "<subject>"
  3. Rebuild the portal:       /portal-build
  4. Add deep dives as needed (one .md per dive in knowledge/deep_dives/)
```
